# Partial arc STRETCH: Windows validation

## Scope and environment

Task: PR #200, Codex, Windows development role, 2026-11-20. The laptop is
Windows x64, OS build 10.0.26300, Intel Core i7-8750H (6 cores, 12 logical
processors). Rust 1.99.0, uv 0.13.0, Python 3.14.10, PySide6 6.12.0.
This machine is not the i7-2600/GT 730 Linux reference floor.

The task first incorporated main `7487c3257a1b6d86280c5dc9f29628669cfc79cf`
with merge commit `c6d4ecd7c53ba8525af5704395f5455f793e7913`, retaining the
ellipse restrictions and all existing main tests. Final acceptance incorporates
main `a7c61065744071e3ea5604c95a48eb2bc22b72b3` through merge
`0f3a84a03b23e33d9bc831f5717d96e035b88c5d`, including subsequent ellipse
editing and rectangular-array preview work. No codec pin, dependency,
CPU baseline, GPU backend or system/application preference is changed.
Qt tests use the project's temporary QSettings isolation and offscreen plugin.

Fixtures are synthetic drawings generated by tests and the 25 public,
SHA-256-checked codec samples fetched by `tools/fetch_codec_samples.py`.
No private drawing is copied or opened, and no original is overwritten.

## What the local checks cover

- Six independent recorded ProgeCAD measurements, A1-A4b in
  [the native observations](stretch-arcs-windows.md), compared against our
  computed centers, radii, angles and endpoints with explicit tolerances.
- Minor, semicircular and major arcs, moving either endpoint; reconstruction
  at scales 1e-4, 1 and 1e4, at the origin and survey coordinates.
- Refusal of collapsed chords, nonfinite intermediates and numerically
  unrepresentable endpoints; no silent approximation beyond the tolerance.
- Normal +Z/-Z, elevation, thickness, color, layer, entity identity and the
  owned model; preview and committed geometry agree within contract tolerance.
- Combined rectangle/polygon selection, deduplicated IDs, index updates,
  one-step undo/redo and whole-transaction rollback, preserving redo history.
- Python command input, Spanish refusal, whole-arc translation controls and
  the actual Qt cursor overlay, which clears on cancellation without editing.
- Six synthetic results each saved and reopened as DWG and DXF (12 outputs),
  retaining geometry, angles, IDs, elevation and color through safe-save guards.

The preview test explicitly applies its change set to the scene before
comparing committed outlines, as the application does through events. The
Qt test uses an exposed, sized window; a collapsed offscreen viewport is not
adequate evidence for a curved preview. Downward OCS round trips can round
an angle's last bit; comparisons use the contract's tolerance, not bit equality.

## Verification status

Before sabotage, 15 focused Rust cases and 42 focused Python/Qt cases passed.
The interrupted first sabotage attempt did not produce a completed result;
its files were restored from exact-byte backups before restarting. The completed
sabotage run detected all deliberate faults: three geometry tests, two document
tests, one core test, ten Python partial-arc cases, and two command/Qt cases
failed for the expected reasons. Exact-byte restoration and extension rebuilding
were followed by all 15 focused Rust and 42 Python/Qt cases passing again.

Final-base acceptance: formatting and Clippy pass; `cargo test` passes 1,021
tests with 20 ignored. The explicit codec corpus run passes all nine selected
tests (two unrelated tests filtered out). `uv run pytest -ra` passes 1,260
tests; six X11-only GPU tests are skipped on Windows. Eleven deprecation
warnings come from existing Qt drag-event constructors in block-palette tests.
Ruff check and format, mypy (206 source files), stubtest and cargo deny all
pass. Fixture verification and `uv sync` pass. Local documentation links and
`git diff --check` pass. Ignored, skipped and unexecuted external/performance
checks are not counted as passing.

## Limits and follow-up

ProgeCAD was not used in this task. Its observations above were recorded on
2026-11-15 and establish the approved behavior; they are not a new independent
reopening of our outputs. Our own-reader round trips are internal checks.
The Qt tests validate the common overlay geometry, not physical GPU pixels.

No benchmark or reference-floor acceptance is claimed. Agree base/candidate
SHAs, synthetic scenarios, build profile, repetitions and acceptance criteria
before measuring. Exercise both partial-arc cursor interaction and unchanged
whole-object/line controls on the actual reference machine, checking CPU and
GPU paths through the existing tools. Startup and backend probing are untouched.

Milestone 02.14 remains in progress; wider STRETCH/AutoCAD compatibility is
not implied. Surface PR #183 is a separate task.
