== (A) The development diagnostic, repeated

TESTING_AND_PERFORMANCE.md, "Path ARRAY diagnostic comparison": 100 lines
i from (100+i%10, 100+i//10) to (+0.5, 0), base (100,100); the guide
((0,0),0), ((L,0),1), ((L+10,0),0) with L = 5*pi; 100 new groups. The
grouped workflow is COPY by point - base and, aligned, ROTATE of the new
ids about the point, of placements computed beforehand (the last at the
stored end, turned 5*pi/2); the atomic one is path_array(ids, guide,
(100,100), 100, align). Each sample is checked: 10,101 entities, the
last group's copy of line 0 from (L+10,0) to (L+10,0.5) aligned or
(L+10.5,0) not, the ARRAYPATH history entry, and undo to 101 entities.
Garbage collection off; 2 warm-ups and 10 samples a run; five runs, the
workflow going first alternating.

Run medians, ms:
  Aligned   COPY/ROTATE  82.75 80.19 78.20 77.02 78.61   pooled 79.39
            ARRAY        39.81 44.30 38.94 40.26 39.35   pooled 40.28
            ARRAY / COPY 0.507
  Kept      COPY         55.32 54.06 52.98 52.49 52.62   pooled 53.74

The development host gave 0.451 and 0.692: the same gain on the floor,
a little smaller, as the floor's slower copies weigh less against the
grouped calls.

== (B) ARRAYPATH in the main window

The real MainWindow, 1366 x 740 (a 1098 x 347 viewport), the renderer it
chooses (OpenGL on the GT 730) or the CPU through safe mode. A generated
DXF: N lines from (100+i%s, 100+i//s) to (+0.5, 0), s = ceil(sqrt N),
and the guide, an LWPOLYLINE (0,0) -> (L,0) -> (L+2R,0) with L = 100*pi,
R = 100 and bulge 1 on the second span (a lower semicircle). The lines
selected, then ARRAYPATH, base 100,100, the guide picked, 100 items,
Align Y. Timed from the command to the copies reported ("command") and
to the first frame painted after the queued events ("first frame");
then zoom extents and 57 pan and 57 zoom frames (after 3 warm-ups), and
the undo to its frame. Three rounds, both renderers and sizes in each.
