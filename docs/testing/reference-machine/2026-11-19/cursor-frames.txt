Method: the real MainWindow on the X11 desktop, with QSettings redirected
to a temporary INI directory and fresh XDG folders. Renderer: the one the
application chooses by itself (OpenGL ES on the GT 730, "gpu"), or the CPU
through MainWindow's safe mode, as --safe-mode ("cpu"). The window was
1366 x 740 ("normal", a 1098 x 347 physical-pixel viewport with the
default panels) or resized until the viewport was 800 x 600 ("small"),
display scaling 1. A generated drawing of 100000 LINEs on a 3-unit grid
(Z 0 for STRETCH, Z 7 for ID) at 20 pixels a unit, centred on (150.5, 150).

The cursor is synthetic: QMouseEvent moves sent through Qt to the
viewport, on a 60 x 40 pixel loop around the centre, 63 moves of which the
first 3 are warm-ups. Each sample is one move plus viewport.repaint(),
which paints the overlay and, on the GPU, presents the frame, so GPU
samples include waiting for the display's 60 Hz refresh. No hand on a
mouse was measured. "idle" is the same loop with no command; "command" is
the loop at STRETCH's displacement prompt (the 100 lines of row 50 picked
with a crossing box around each end, base point 0,0) or at ID's point
prompt. Medians and 95th percentiles, ms:

Checked on every run:
- STRETCH: the candidate's overlay held 109 one-pixel strokes during the
  displacement prompt (the 100 stretched outlines among them), the base's
  9 (no outlines). Cancelling left the history unchanged; the same
  selection with displacement 2,3 typed in moved the first line's end by
  exactly (2, 3) as one undo step, and undo restored it.
- ID: cancelling left the history unchanged. At the loop's last position
  the candidate in SW isometric held an END snap; the base, which cannot
  snap there, none.

Reading:
- With the GPU, every frame is the display's refresh (16.4-16.7 ms
  medians) before and after both changes: the added work fits inside the
  frame.
- On the CPU, STRETCH's live preview adds about 2.7-3.5 ms to a cursor
  frame with 100 stretched lines (4.2 -> 6.9 ms normal, 4.4 -> 7.8 ms
  small), its 95th percentile 10-11 ms: still within one 60 Hz frame.
  The base shows no outlines, so this is the cost of a new feature, not a
  slowdown of an old one.
- ID costs the same before and after on the CPU and the GPU. The CPU's
  idle loop in SW isometric (about 7 ms against 1.5 ms in Top) is the same
  in both revisions; why was not looked into in this session. One idle
  CPU run, ID Top small on the candidate (3.53 ms against the base's
  1.60), stands apart from the other idle Top runs (1.45-1.77 ms); it ran
  with no command active and was not repeated.
