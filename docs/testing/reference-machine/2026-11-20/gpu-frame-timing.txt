Compared local commits c19705b (A) and 763c69c (B) in one X11 session.
Intel Core i7-2600, GeForce GT 730 (NV106), LMDE 7, kernel 6.12.117,
Mesa 25.0.7, 1920 x 1080 at 60 Hz. Both extensions used the release
profile, the same Cargo and uv lockfiles, and Python 3.13.5. Verified
that the extensions differ and that only B exposes rectangular array
outlines. The two commits have identical benchmark, GPU renderer, and
GPU overlay source files. The benchmark selected the OpenGL hardware
adapter in both builds. The desktop and browsers were left open.

The GPU was slower in both builds than the preceding reference reports.
Candidate-to-baseline GPU ratios were 1.08 for median pan, 1.00 for
median zoom, 0.95 for pan p95, and 1.11 for zoom p95. The ranges of all
four GPU statistics overlap and the direction of the difference changes
across adjacent pairs. The high frame times reproduce on the older
commit. Three passes per build in a single desktop session leave the
size and cause of any commit-specific effect unresolved.

Stage timings

After the comparison, rebuilt B with temporary Instant checkpoints in
GpuRenderer::present. The intervals bracketed retained geometry and
uniform preparation, surface acquisition, overlay preparation and
encoder setup, queue submission (including encoder.finish), queue
presentation, and the final error check. The harness marked the pan
and zoom loops, and recorded 60 successful frames in each loop. The
analysis drops the first three frames and groups the remaining frames
by whether the sum of the Rust intervals exceeded 25 ms. The complete
repaint in this instrumented run was 27.1/51.3 ms for pan and
31.2/51.1 ms for zoom (median/p95). The instrumented data is separate
from the comparison between builds.

* Frames exceeding 25 ms. Entries are medians in milliseconds. Each
column is aggregated separately, so the total need not equal the sum
of the displayed columns.

The median queue presentation call accounts for about 98% of the
median Rust time in each slow-frame group. On this OpenGL backend the
call includes making the EGL context current, a framebuffer blit and
the buffer swap. The checkpoints measure CPU-side elapsed time, so
they cannot distinguish GPU completion, buffer swapping, compositor
scheduling or other waits inside the presentation call.
