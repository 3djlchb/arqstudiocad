# 0011. Document model, transactions and undo

Date: 2026-10-11 · Status: Accepted · Builds on [0002](0002-dwg-native-format.md),
[0008](0008-opencadcodec.md), [0010](0010-geometry-conventions.md)

## Context

Phase 3 builds `arq-document` (the drawing) and `arq-core` (operations,
transactions, history, queries) on top of opencadcodec. The analysis of the
codec (`docs/references/opencadcodec-internals.md`) showed that its
`CadDocument` is the DWG database in memory, keeps entities behind shared
`Arc`s with copy-on-write, and ships a first-touch change recorder designed
for undo. A trial build confirmed it compiles with our toolchain, is
`Send + Sync`, and round-trips DXF and DWG (AC1032) keeping handles.

## Decision

### D3.1 — Codec version

Git dependency pinned to commit **`8189f83`** (the one Open CAD Studio uses;
the codec publishes no tags). It is updated only by a deliberate commit, after
our DWG/DXF round-trip corpus passes. `deny.toml` allows that git source.

### D3.2 — Storage

The codec's `CadDocument` is the **only store**. `arq-document` exposes our own
API: reads translate codec entities into our types (`Geometry2` plus
properties); edits write into the codec. No second copy, nothing lost: what we
do not understand stays untouched. Codec types never leave `arq-document`
(ADR 0008).

### D3.3 — 2D on a 3D format

Entities drawn **in plan** are editable as 2D: normal `(0,0,1)` and also
`(0,0,-1)`, converted with the arbitrary-axis rule (port of IngeCAD's
`ocs.py`: X negated, angles mirrored, arc direction reversed). Their **Z
(elevation) and thickness are preserved** across edits. Entities on tilted
planes are kept intact and are **read-only**.

### D3.4 — Entity types not yet supported

The other 45 codec entity types are **kept intact on save**, listed with their
type and layer, and **can be erased** (erasing needs no geometry). They become
editable in their own phases.

### D3.5 — Undo / redo

**Transactions with before/after images.** Each transaction turns on the
codec's change recorder; the first touch of an entity stores its previous
image (an `Arc`, no geometry copy). Commit pushes `{handle: before → after}`
onto the history; undo restores the before images, redo the after images.
Table and structure changes (layers…) use the codec's structure snapshots.
No command writes its own undo.

The recorder identifies the document by its memory address, so the
`CadDocument` lives in a `Box` and never moves while recording.

### D3.6 — Identifiers

`EntityId` = the entity's DWG handle; `LayerId` = the layer's handle (`u64`).
Stable across save and open, never reused within a document (contract §10).

### D3.7 — Change sets

Every committed transaction returns a `CadChangeSet` with entities created,
modified and deleted; layers created, modified and deleted; and a flag for
document-level changes (units, settings). The UI refreshes only what changed.

### D3.8 — Spatial index

Deferred to phase 7 (proposal R6). In phase 3, `query_entities(bounds)` scans
all entities behind a stable interface, with a benchmark to measure later.

Queries return candidates by bounding box and ignore layer state; callers
filter. Baseline (`cargo bench -p arq-core`, development machine,
2026-10-12, 100,000 entities): about 17 ms for `bounds()` or one query,
whatever the window size, so the scan dominates; one recorded change plus
its undo takes about 1.5 µs.

### D3.9 — Grouping

Every core operation is **one transaction by itself** (one undo step).
Commands that combine operations wrap them in a **group**: one undo reverts
the whole group, and a failure inside rolls the whole group back.

### D3.10 — Threads

**One mutation stream per document** (contract §9), guarded by a lock.
Long reads — saving, autosave — work on a cheap snapshot (shared `Arc`s), so
they never block drawing.

`CadApplication` keeps each open document behind its own `Mutex`: one call
at a time per document, the lock held only for that call. A `RwLock` for
parallel queries can replace it later without changing the API. Saving holds
the lock only to take the snapshot (about 4.5 ms at 100,000 entities on the
development machine, 2026-10-12) and writes the file without it. Whether a
document is modified follows its history: undoing back to the saved state
makes it unmodified again. A panic while a document is locked (a bug) makes
that document refuse further calls; it can still be closed.

### D3.11 — Properties editable in phase 3

**Layer and color** (ByLayer, ACI index or true color). Linetype, lineweight
and transparency are read and preserved; editable in the properties phase.

### D3.12 — Round-trip corpus

Three sources, none committed as third-party files:

1. drawings **generated by our tests**, saved as DXF and DWG in several
   versions and read back;
2. the **codec's own sample files** (MPL-2.0), downloaded by the test tooling;
3. a **local folder of the maintainer's real drawings**, tested when present
   (path from an environment variable), **never pushed** — they may be
   client work.

## Consequences

- `arq-core` never sees codec types; replacing or forking the codec stays a
  change inside `arq-document`.
- Undo is cheap in memory and cannot be forgotten by a command.
- Unsupported entities survive every edit and save, at the cost of being
  read-only until their phase.
- The pinned commit and the corpus are the guard against regressions in a
  single-maintainer dependency.
